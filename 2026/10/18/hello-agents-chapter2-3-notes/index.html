Hello-Agents 第二、三章学习笔记：从符号主义到 Decoder-Only

发表于2026-10-18|更新于2026-10-18|学习笔记

以《Hello-Agents》第二、三章为线索，把智能体发展史、Transformer 原理、分词与推理串成一条线。文中保留了我在动手过程中真正卡住的问题，并附上实测结论和面试向总结。

🧭 一、先给一条主线：范式是「问题驱动」迭代出来的

学完这两章，我最想先记下来的不是某个公式，而是这条主线：

每一个新范式的出现，都是为了解决上一代范式的核心痛点；而它在带来能力飞跃的同时，又引入了新的局限，为下一代范式埋下伏笔。

这句话解释了为什么今天的大模型长成这个样子。把历史串起来看：

理解这条线，比记住任何一个单独的知识点都重要。下面的内容基本就是沿着它展开的。

🏛️ 二、智能体的前史：符号主义的三次碰壁

2.1 物理符号系统假说：智能 = 符号计算

1976 年，纽厄尔和西蒙提出物理符号系统假说（PSSH），包含两个论断：

  1. 充分性：任何物理符号系统，都具备产生通用智能行为的充分手段。
  2. 必要性：任何能展现通用智能的系统，本质上必然是物理符号系统。

它把”什么是智能”这个哲学问题，转化成了”如何表示知识、如何设计推理算法”的工程问题。在那个年代，这个假说给了研究者极大的信心。

2.2 专家系统与 SHRDLU

符号主义最成功的产物是专家系统：把领域专家的知识编码成 IF-THEN 规则，让机器在特定领域给出媲美专家的结论。

另一个标志性项目是 SHRDLU——它能理解自然语言指令、操作积木世界、回答关于场景的问题，在当时看来近乎”通用智能”。但它的成功有一个前提：运行在一个规则完备的封闭世界里。

2.3 为什么符号主义走不通

从 20 世纪 80 年代起，符号主义在走向开放世界时撞上了四面墙：

（1）知识获取瓶颈
专家知识要靠人工访谈、提炼、编码，成本高、难规模化。更麻烦的是，人类大量知识是内隐的、直觉的，根本说不清自己是怎么判断的，自然也没法写成规则。

（2）常识问题
人类行为依赖庞大的常识背景（”水是湿的””绳子能拉不能推”），但符号系统不明确编码就一无所知。Cyc 项目为此努力数十年，成果依然有限。

（3）框架问题
智能体执行一个动作后，如何高效判断”哪些事物没变”是个逻辑难题。为每个动作显式声明所有不变状态，计算上不可行。

（4）系统脆弱性
规则之外的一点变化就可能让系统完全失灵。SHRDLU 的成功恰恰因为它待在一个封闭世界里，而真实世界充满例外。

这四条，本质上是同一句话：靠人把世界显式编码出来，规模上不可行。

2.4 ELIZA：规则聊天机器人的启示

ELIZA 是早期基于规则的聊天机器人。它的核心是模式匹配 + 文本替换：用正则匹配用户输入，再从模板库里挑一句回应。比如把”我觉得 X”转成”你为什么觉得 X？”

它带来的启示很有意思：人很容易把”像人一样的语言行为”误认为”真的理解”。这被称为”ELIZA 效应”。它也提醒我们，判断一个系统是否真的”智能”，不能只看它说话像不像人。

2.5 明斯基的心智社会：从单体到协作

马文·明斯基提出心智社会（Society of Mind）：智能不是某个中心模块的产物，而是大量简单单元交互后涌现出来的整体行为。

这个思想在当时没有直接落地，但它为后来的多智能体系统提供了哲学基础——今天的多 Agent 协作、分工、辩论，本质上都能在这里找到源头。

🎓 三、学习范式：从「被设计」到「被训练」

符号主义的困境引出了一个关键问题：

如果智能无法被完全设计，那它能不能被学习出来？

3.1 联结主义：知识存在权重里

联结主义是自下而上的思路，灵感来自生物神经网络：

  • 分布式表示：知识不存放在明确的符号规则里，而是分布在大量神经元的连接权重中
  • 简单单元：每个神经元只做加权求和 + 激活函数
  • 学习调整权重：通过反向传播等算法，根据样本自动迭代权重

和符号主义最大的区别：符号主义把知识显式编码给机器，联结主义让机器自己学出知识。

它解决了感知问题（”这张图里有什么”），但还不擅长决策（”我接下来该做什么”）。

3.2 强化学习：在试错中学会决策

强化学习（RL） 专注序贯决策，核心框架由五个要素构成：

要素 含义 AlphaGo 中的例子
Agent 学习者和决策者 决策程序
Environment 外部世界 围棋规则和对手
State 环境的当前描述 棋盘布局
Action 可采取的操作 落子位置
Reward 行动的评价信号 赢了 +1，输了 −1

工作循环是：观察状态 → 按策略选行动 → 环境转移并给奖励 → 更新策略。

目标是最大化累积奖励（回报），而不是即时奖励——所以智能体需要”远见”，有时要牺牲眼前利益（围棋里的”弃子”）。

3.3 预训练：解决知识获取瓶颈

RL 智能体虽然会决策，但缺乏先验知识，每个任务都从零开始。解决方案来自 NLP：

预训练 + 微调 两步走：

  1. 预训练：在海量互联网文本上做自监督学习，目标就是”预测下一个词”。学的是语言规律、事实知识和上下文逻辑。
  2. 微调：针对下游任务，用少量标注数据调整。

这一步真正解决了符号主义最头疼的知识获取瓶颈：知识不再需要人工编码，而是从数据中自动压缩进模型权重。

更惊人的是涌现能力（Emergent Abilities）——当规模跨过某个阈值后，模型会突然具备训练目标之外的能力：

  • 上下文学习（In-context Learning）：给几个示例甚至零示例，就能完成新任务
  • 思维链推理（Chain-of-Thought）：引导模型先输出推理步骤，复杂任务准确率显著提升

3.4 LLM 驱动的现代智能体：感知 → 思考 → 行动 → 观察

到这里，历史的技术拼图汇合了：

  • 符号主义提供了逻辑推理框架
  • 联结主义和 RL 提供了学习与决策能力
  • LLM 提供了世界知识和通用推理

现代智能体的闭环可以抽象为：

  • 感知：接收用户指令、API 返回、环境状态
  • 思考：规划模块拆解目标，LLM 结合记忆做推理和决策
  • 行动：执行模块解析工具调用，真正去调 API / 跑代码 / 搜网页
  • 观察：工具结果和环境新状态反馈回来，更新记忆，进入下一轮

第一章那个”查天气 + 推景点”的小 Agent，就是这条闭环的最小实现。

📈 四、语言模型的三级跳：N-gram → 词嵌入 → RNN

4.1 N-gram：用马尔可夫假设做计数

语言模型的根本任务是计算一个词序列出现的概率。按链式法则：

$$P(w_1,\dots,w_m)=P(w_1)\cdot P(w_2\mid w_1)\cdots P(w_m\mid w_1,\dots,w_{m-1})$$

但长条件概率几乎无法从语料中估计——那个词序列可能从没出现过。

于是引入马尔可夫假设：一个词只和它前面有限的 $n-1$ 个词有关。这就是 N-gram。

  • Bigram（N=2）：$P(w_i\mid w_{i-1})$
  • Trigram（N=3）：$P(w_i\mid w_{i-2},w_{i-1})$

概率用最大似然估计，说白了就是数数：

$$P(w_i\mid w_{i-1})=\frac{Count(w_{i-1},w_i)}{Count(w_{i-1})}$$

局限：上下文窗口固定；没见过词对概率直接为 0（数据稀疏）；只记住了字面组合，没有泛化能力。

4.2 词嵌入：king − man + woman ≈ queen

神经网络语言模型的关键创新是词嵌入：把词映射成稠密向量，而且这些向量是在训练”预测下一个词”的过程中自动学出来的。

有了向量就能算相似度，最常用的是余弦相似度：

$$\text{similarity}(\vec a,\vec b)=\frac{\vec a\cdot\vec b}{|\vec a||\vec b|}$$

  • 方向相同 → 1
  • 正交 → 0
  • 方向相反 → −1

最经典的例子：vector(King) − vector(Man) + vector(Woman) 在向量空间里非常接近 vector(Queen)。这说明向量不仅编码了”词义”，还编码了”性别””皇室”这类抽象关系。

这一步解决了 N-gram 的泛化问题：没见过”国王 + 女性”的组合，也能通过向量运算推出”女王”。

但它仍有一个和 N-gram 类似的毛病：上下文窗口固定。

4.3 RNN/LSTM：给网络加上记忆

RNN 引入隐藏状态作为”短期记忆”：每一步读取当前词 + 上一步的隐藏状态，生成新的隐藏状态传给下一步。信息可以在序列中向后传递，不再受固定窗口限制。

问题是长期依赖：训练时梯度要沿序列反向传播，长度一长就会梯度消失或梯度爆炸，早先的信息学不进去。

LSTM 用细胞状态 + 门控机制缓解了这个问题：

门 作用
遗忘门 决定从上一时刻的细胞状态丢弃什么
输入门 决定当前输入中哪些新信息存进去
输出门 决定从细胞状态输出什么到隐藏状态

细胞状态像一条独立的信息高速公路，让梯度能更顺畅地跨越较长的距离。

🏗️ 五、Transformer 架构拆解

5.1 整体结构：编码器 + 解码器

原始 Transformer 由两部分组成：

  • Encoder 层：多头自注意力 → 残差 + LayerNorm → 前馈网络 → 残差 + LayerNorm
  • Decoder 层：掩码自注意力 → 交叉注意力 → 前馈网络，每步都配残差 + LayerNorm

关键创新是自注意力：任意两个位置之间都能直接建立联系，路径长度是 O(1)，而且可以并行计算——这正是 RNN 做不到的。

5.2 位置编码：i 到底是什么

自注意力本身没有顺序概念（打乱输入顺序，结果不变），所以必须额外注入位置信息。

公式：

$$PE_{(pos,2i)}=\sin\left(\frac{pos}{10000^{2i/d_{model}}}\right),\qquad
PE_{(pos,2i+1)}=\cos\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$

i 是”成对的维度编号”，不是单个维度编号：

  • 偶数维度 2i → 用 sin
  • 奇数维度 2i+1 → 用 cos
  • 范围 i = 0, 1, ..., d_model/2 − 1，共 d_model/2 组，拼起来正好 d_model 维

实例：d_model = 4

此时 div_term = [1, 0.01]（因为 10000^{-2/4} = 0.01），于是：

i 维度 取值
0 dim0（sin） sin(pos / 10000^(0/4)) = sin(pos)
0 dim1（cos） cos(pos / 10000^(0/4)) = cos(pos)
1 dim2（sin） sin(pos / 10000^(2/4)) = sin(pos/100)
1 dim3（cos） cos(pos / 10000^(2/4)) = cos(pos/100)

所以一个位置 pos 的编码是 [sin(pos), cos(pos), sin(pos/100), cos(pos/100)]，长度 4。

核心意义：不同 i 对应不同周期。小 i 周期短、分辨率高，捕捉细粒度位置；大 i 周期长，捕捉远距离关系。多种频率叠加，模型才能同时感知近处和远处的相对偏移。

易错点：i 的范围是 0 ~ d_model/2，不是 0 ~ d_model。一个 i 控制一对 sin/cos。

torch.arange(0, d_model, 2) 生成的是 [0, 2, 4, ...]，正好对应 2i；exp(-ln(10000)·2i/d_model) 等价于 10000^(-2i/d_model)。

5.3 register_buffer：为什么位置编码不参与训练

分两部分看：

① pe.unsqueeze(0)：在最前面加一个长度为 1 的维度，[max_len, d_model] → [1, max_len, d_model]。这样输入 [batch_size, seq_len, d_model] 就能通过广播直接相加，不需要手动复制 batch 份。

② register_buffer：把张量注册为模块缓冲区，特点是：

  • 不是模型参数，不被优化器更新，也不求梯度（位置编码是固定公式算好的）
  • 会进 state_dict，随模型一起保存和加载
  • 自动跟随模型迁移设备（.to(device) / .cuda()）

对比：

是否训练 是否存盘 是否随模型迁移设备
nn.Parameter ✅ 会更新 ✅ ✅
register_buffer ❌ 不更新 ✅ ✅
普通属性 self.x = tensor ❌ ❌ ❌

前向传播里：x = x + self.pe[:, :x.size(1), :]，第 1 维截到当前序列长度再加。

5.4 位置编码之后为什么加 Dropout

先看顺序：

不会破坏位置信息，原因有三：

  1. 位置编码本身高度冗余：它是多频率正弦的叠加，丢掉部分维度后，剩下的维度仍足以表达相对位置。就像一首歌有很多音轨，静音几条还能听出旋律。
  2. Dropout 是正则化：强制模型不依赖少数几个维度，学出更鲁棒的特征，防止过拟合。
  3. 推理阶段自动关闭：model.eval() 下 Dropout 不生效，向量完整保留，位置信息一点不丢。

5.5 自注意力 vs 交叉注意力

两者计算公式完全一样：

$$Attention(Q,K,V)=softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

唯一区别是 Q、K、V 的来源。

项目 自注意力 交叉注意力
Q 来源 同一输入 Decoder 当前输出
K、V 来源 同一输入 Encoder 的 memory
序列长度 seq_q = seq_k 可以不同
作用 看自己内部 token 的关系 用 Q 去检索另一段序列的信息

5.6 剩下的拼图

  • 多头注意力：把 d_model 切成 num_heads 份，每个头独立算注意力，再拼接。不同的头可以关注不同类型的关系（语法、指代、位置等）。
  • 缩放因子 1/√d_k：点积的方差会随维度增大，不缩放会让 softmax 进入饱和区，梯度变得很小。
  • 残差连接：x + sublayer(x)，缓解深层网络的梯度消失。
  • LayerNorm：稳定训练。原论文用 Post-LN，很多现代实现用 Pre-LN。
  • 前馈网络（FFN）：两层线性 + 激活，先升维到 d_ff 再降回 d_model，提供非线性变换能力。
  • 掩码（Mask）：Decoder 的自注意力用因果掩码，保证只能看到左边已生成的 token。

🏆 六、Decoder-Only：为什么它赢了

6.1 两种架构的比喻

Encoder-Decoder（T5、BART） 像”翻译员 + 记录员”两人组队：Encoder 通读原文做笔记（memory），Decoder 一句句写输出，写的时候看笔记（交叉注意力）保证不跑偏。

Decoder-Only（GPT、Llama、Qwen） 像”单人作家”：把提问和回答写在同一条纸上，只能看左边已写好的字（掩码自注意力），不断往下续写。没有编码器，也没有交叉注意力。

6.2 对比

项目 Encoder-Decoder Decoder-Only
模块 Encoder + Decoder，有交叉注意力 只有带掩码的 Decoder
注意力 Encoder 双向；Decoder 单向 + 交叉 全部单向掩码自注意力
工作方式 先编码成 memory，再交叉注意力读取 prompt 和回答拼成长序列，自回归续写
典型模型 T5、BART、原始 Transformer GPT、Llama、Qwen、Mistral
擅长 翻译、摘要（输入输出界限清晰） 通用对话、续写、代码、问答

补充：Encoder-only（BERT） 只有编码器、双向注意力，不能生成文本，只做理解类任务（分类、抽取）。

6.3 为什么主流大模型选 Decoder-Only

  1. 架构简单：一套网络权重，没有编码器和交叉注意力，工程、训练框架、显存优化都更容易，更适合堆到千亿参数。
  2. 任务形式统一：问答、翻译、摘要、写代码，全部转化为”给一段 prompt 续写”，一个模型通吃。
  3. 训练数据易获取：预训练目标就是”预测下一个 token”，海量互联网连续文本直接可用；Encoder-Decoder 需要高质量的输入-输出配对数据，稀缺得多。
  4. 推理部署方便：一套自回归逻辑；Encoder-Decoder 要先跑编码器，再跑解码器 + 交叉注意力，链路更复杂。
  5. 长上下文友好：所有上下文拼成一条序列，统一用单向注意力处理。

短板：没有双向编码器，长输入的理解要靠大参数量 + 长上下文窗口弥补；prompt 越长，每次生成的计算开销越大（Encoder-Decoder 可以把编码结果缓存住，生成阶段不重算）。

✂️ 七、分词：BPE 如何把文字切成 token

7.1 为什么需要分词

模型只认数字，不认文字。分词（Tokenization） 就是把文本切成 token，再映射成 ID。

粒度选择是个权衡：

  • 按字/词切：词表爆炸，且遇到未登录词（OOV）就没办法
  • 按字符切：词表小，但序列太长，语义太碎
  • 子词（subword）：折中方案——常见词保持完整，生僻词拆成片段

BPE（Byte Pair Encoding） 是最经典的子词算法，GPT、BERT 的分词器底层都用它。

7.2 核心思想

不断统计相邻 token 对的频次，把最高频的一对合并成新 token，循环多轮。

直觉是：高频共现的片段应该被当作一个整体。比如 e 和 s 经常相邻，就合并成 es；es 和 t 经常相邻，再合并成 est。

7.3 逐行拆解实现

几个容易看错的点：

  • collections.defaultdict(int)：访问不存在的 key 时自动返回 0，省掉 if key not in dict 的判断。
  • pairs[symbols[i], symbols[i+1]] += freq：累加的是该词的频次。假设 u g 在词频为 5 的词里出现，它就加 5，而不是加 1。
  • re.escape()：把 pair 里的正则特殊字符转义掉，避免被当成元字符。
  • (?<!\S) ... (?!\S)：只匹配被空白包围的完整词元对。(?<!\S) 是”前面不是非空白字符”（即行首或空格），(?!\S) 是”后面不是非空白字符”。这样不会把 x u g y 中间片段误当成 u g。
  • p.sub(''.join(pair), word)：把 "u g" 替换成 "ug"，即去掉中间空格。

主循环：

  • max(pairs, key=pairs.get)：按字典的值（频次）取最大的 key。
  • if not pairs: break：没有可合并的对时提前退出。
  • 每轮只合并一对全局最高频，不是一次性合并所有相同的 pair。

7.4 </w> 和断言的作用

  • </w> 标记单词结尾，用来区分”词内字符”和”词尾字符”。没有它，low 和 lower 的 low 就没法区分。
  • 正则断言保证只匹配完整相邻词元，防止跨词误合并。

💬 八、提示工程：怎么和模型「说话」

模型的能力再强，也需要通过提示（Prompt） 引导。对智能体来说，提示设计直接影响它的规划和决策质量。

8.1 采样参数：Temperature / Top-k / Top-p

模型每步输出的是词表上的概率分布。采样参数的作用就是调整或截断这个分布。

Temperature：把 Softmax 改写成

$$p_i^{(T)}=\frac{e^{z_i/T}}{\sum_j e^{z_j/T}}$$

  • T 小 → 分布更陡峭，高概率项被放大，输出更确定、更重复
  • T 大 → 分布更平坦，低概率项权重上升，输出更多样但可能不连贯
温度区间 特点 适用场景
0 ~ 0.3 精准、确定 问答、数据计算、代码生成、法律/技术文档
0.3 ~ 0.7 平衡、自然 客服对话、邮件、产品文案
0.7 ~ 2 创新、发散 诗歌、故事构思、广告脑暴

Top-k：按概率排序，只保留前 k 个 token 作为候选集，再归一化采样。k=1 退化为贪心采样。

Top-p（核采样）：按概率从高到低累加，直到累积和 ≥ p，取这个最小集合作为候选集。相比固定截断的 Top-k，Top-p 能动态适应不同分布的长尾特性。

三者同时设置时，优先级是：温度调整 → Top-k → Top-p。不过通常 Top-k 和 Top-p 二选一即可，同时设置时实际候选集是两者的交集。

两个极端：

  • Temperature = 0 → Top-k / Top-p 都无关紧要，直接取最高概率
  • Top-k = 1 → 温度和 Top-p 都无关紧要，只有一个候选

8.2 Zero-shot / Few-shot / CoT

类型 做法 依赖
Zero-shot 不给示例，直接下指令 预训练带来的泛化能力
One-shot / Few-shot 给 1 个或多个示例 上下文学习能力
Chain-of-Thought 要求”一步一步思考” 涌现出的推理能力

CoT 的价值不只是提高准确率，还让推理过程可见、可检查、可纠正——这对智能体的可靠性很重要。

⚖️ 九、模型怎么选

选模型不是”越大越强”这么简单，而是性能、成本、速度、部署方式之间的权衡。可以从八个维度评估：

  1. 性能与能力：不同模型擅长的任务不同，参考 LMSys Chatbot Arena 等排行榜
  2. 成本：闭源按 Token 计费；开源看 GPU/内存和运维
  3. 速度（延迟）：实时交互场景（客服、游戏 NPC）尤其重要
  4. 上下文窗口：长文档分析、代码库理解、长期记忆需要 128K 甚至更大
  5. 部署方式：API 简单但数据出第三方；本地部署隐私可控但硬件要求高
  6. 生态与工具链：社区、教程、微调工具、框架支持（LangChain、LlamaIndex、Transformers）
  7. 可微调性：领域数据定制化，开源模型灵活性更大
  8. 安全与伦理：偏见、毒性、幻觉，以及服务商的负责任 AI 投入

闭源 vs 开源：

  • 闭源（GPT、Gemini、Claude、文心/混元/星火等）：开箱即用，代表前沿水平
  • 开源（Llama、Mistral、Qwen、ChatGLM 等）：可本地部署、可微调、可控性最高

一句话：闭源给你便捷，开源给你自由。

📊 十、缩放法则与固有局限

10.1 Scaling Laws 与 Chinchilla

缩放法则揭示了模型性能与参数量、数据量、计算量之间的幂律关系：在对数-对数坐标下，Loss 随三者平滑下降，没有明显瓶颈。

早期大家只盯着参数量，直到 DeepMind 2022 年提出 Chinchilla 定律：在给定计算预算下，参数量和训练数据量存在最优配比。最优模型往往比之前认为的更小，但需要多得多的数据。

典型例子：700 亿参数的 Chinchilla 用了比 1750 亿参数的 GPT-3 多 4 倍的数据训练，性能反而更好。这纠正了”越大越好”的片面认知，也指导了后来 Llama 系列的设计。

10.2 涌现能力

当规模跨过某个阈值，模型会突然展现出小模型没有的能力：

  • 上下文学习：几个示例就能完成新任务
  • 指令遵循：理解并执行自然语言指令
  • 多步推理：Chain-of-Thought
  • 代码生成

这说明大模型不只是”记忆和复述”，可能形成了更深层的抽象能力。对智能体开发者来说，选一个足够大的模型，是实现复杂自主决策的前提。

10.3 幻觉：模型为什么会一本正经地胡说

幻觉（Hallucination） 指模型生成与客观事实、用户输入或上下文相矛盾的内容。

根源在于：模型不是数据库，没有内置的事实核查模块，它的本质是预测下一个最可能的 token。句子通顺、概率高，不代表事实正确。

常见分类：

类型 含义
事实性幻觉 生成与现实世界不符的信息
忠实性幻觉 摘要/翻译等任务未忠实反映源文本
内在幻觉 生成内容与输入信息直接矛盾

（也有人按”内部/外部”分：内部指与上下文冲突，外部指编造上下文之外的事实。）

成因：

  1. 训练数据里有错误或矛盾的信息
  2. 自回归生成机制只做概率预测，没有事实核查
  3. 复杂推理时中间步骤出错，导致”编造”结论

缓解手段：

  • RAG（检索增强生成）：生成前先检索外部知识，把结果作为上下文
  • 提示词约束：要求”不知道就说不知道，禁止编造”
  • 调低 temperature：降低随机性
  • 多步推理 + 自我验证
  • 引入外部工具：搜索引擎、计算器、代码解释器
  • 输出后校验：事实类内容做检索核对

此外还有两个容易被忽略的局限：知识时效性不足（训练数据有截止日期）和训练数据偏见（模型会吸收并反映数据中的刻板印象）。

🛠️ 十二、两个工程杂记

12.1 Python GIL：为什么多线程跑不快 CPU 密集任务

GIL（全局解释器锁）是 CPython 的一把锁：同一时刻，一个进程内最多只有一个线程真正执行 Python 字节码。

想象一个房间只有一把钥匙，工人（线程）要干活必须抢到钥匙，一次只能进一个人。哪怕多核 CPU，同一进程的多个线程也无法真正并行跑 Python 代码，只能轮流交替——是并发，不是并行。

GIL 什么时候释放？

  1. IO 等待（最常见）：等网络、读文件时主动交出 GIL
    • ✅ IO 密集型任务，多线程依然有效（爬虫、文件读写、接口请求）
  2. 运行足够多字节码后：CPU 密集任务会被强制交出锁
    • ❌ CPU 密集任务，多线程不提速甚至更慢（抢锁有开销）

怎么绕开？

  1. 多进程 multiprocessing：每个进程有独立解释器和独立 GIL，可真正并行。代价是进程重、通信开销大。
  2. 交给 C 扩展：numpy、pandas 底层是 C，执行期间可释放 GIL，实现多核并行。

面试一句话：GIL 是 CPython 的全局解释器锁，保证同一时刻一个进程内只有一个线程执行 Python 字节码。它让多线程无法利用多核做 CPU 密集并行；但 IO 阻塞时释放锁，IO 密集场景多线程依然有效。

12.2 pip 的警告与依赖冲突

Successfully installed 出现了，就是装成功了。 最后的提示分两类，都不影响 import：

  1. PATH 警告（scripts not on PATH）：只是命令行不能直接敲脚本命令，不影响 import 库。可以加 --no-warn-script-location 关掉提示。
  2. 依赖冲突（如 openxlab requires rich~=13.4.2, but you have rich 15.0.0）：新包升级了某个依赖，与已装的包版本不匹配。不影响新装的包本身，但那个旧包可能报错。修复方式：pip install rich==13.4.2 降级。

📌 十三、总结

把这两章压缩成几句话：

  1. 智能体发展史是一条”问题驱动”的线：符号主义受困于知识获取瓶颈，联结主义解决了感知，强化学习解决了决策，预训练解决了知识来源，LLM 把它们整合成了现代智能体。
  2. 语言模型经历了 N-gram → 词嵌入 → RNN/LSTM → Transformer 的演进，每一步都在解决上一步的硬伤：稀疏性、泛化、长依赖、并行性。
  3. Transformer 的核心是自注意力：任意位置直接建联、可并行。位置编码补回顺序，交叉注意力让解码器读取编码器，残差 + LayerNorm + FFN 撑起深层网络。
  4. Decoder-Only 成为主流，是因为它架构简单、任务统一、数据易得、部署方便、适合扩展。
  5. 模型不是数据库：它做的是概率预测，所以会幻觉、会过时。用 RAG、提示约束、外部工具和多步验证来兜底。
  6. 工程细节同样重要：分词决定模型怎么看世界，采样参数决定输出风格，环境配置决定你能不能跑起来。

如果只记一句话：

理解了”每一代范式在解决什么问题、又留下了什么新问题”，就理解了今天的大模型为什么是这个样子。
